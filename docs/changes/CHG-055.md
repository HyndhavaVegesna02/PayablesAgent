The public docs/evals put 27 dated run folders and 8 workflow files at one level. A judge met ABORTED rows
with Google's raw 429 text before any result, and couldn't tell which folder answers which deliverable.
No Gemini calls, and no measured result changes: only locations, generated wording, and the ablation's
coverage rule (AC4).

## Acceptance Criteria
- [ ] AC1: docs/evals is laid out by deliverable (1-eval-report, 2-harness-ablation,
  3-improvement-and-regression, 4-end-to-end-workflows, raw-runs), each with a README. Every moved live report
  is a pure rename.
- [ ] AC2: The combined suite page opens with a generated Coverage line: runs scored of planned, the
  invocations and commits, and every scenario whose row a later invocation replaced, with the earlier results.
  The totals say "N of M finished runs passed (P%), E errored".
- [ ] AC3: Both combined pages give each source's status in plain words, true to its recorded reason, with a
  "runs used here" column and one generated sentence on what a stopped invocation's runs count for.
- [ ] AC4: The combined ablation page gives each harness's coverage (scenarios scored, runs per cell). A paired
  drop shows only for a harness scored on more than half the scenarios; otherwise "not measured live (n/N
  scenarios)", and it is out of "earned the most". "Earned the most" says one run per scenario and points to
  the offline ablation.
- [ ] AC5: docs/evals/README.md maps each deliverable to its headline and link. Every figure a docs/evals
  README quotes is asserted by a test against its report.json.
- [ ] AC6: check-evidence finds every report in the new layout, at least as many as before. make evals and
  make ablation write to raw-runs/, make workflow to 4-end-to-end-workflows/.
- [ ] AC7: Every relative link in README.md and docs/**/*.md resolves (a test), anchors included.
