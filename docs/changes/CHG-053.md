id: CHG-053
title: A model that was unavailable never scores as a harness failure; the budget guard stops on a 402 credit-depleted refusal (PO, batch 18)
type: defect
---

Live ablation v2 (2026-10-04): Gemini's prepaid credits ran out mid-invocation and every call came back
`402 RESOURCE_EXHAUSTED`. The guard stopped only on a spend-cap 429, so the invocation went on, and the full
system's knock-outs scored those runs as FAILED at zero cost (docs/evals/invalid/2026-10-04-credits-depleted/).

## Acceptance Criteria
- [ ] AC1: The budget guard treats a 402 (and any permanent billing, prepayment or credit refusal) as it treats
  the spend-cap 429: it stops the invocation at once, and `stopped_because` names it.
- [ ] AC2: Any run in which the model was unavailable (AIUnavailable, permanent, or retryable on a job's last
  attempt) is scored ERRORED, never FAILED, and doesn't count toward a harness's success rate.
- [ ] AC3: Tests drive a 402 in the middle of an invocation, in both the runner and the ablation.
