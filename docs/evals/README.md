# Eval reports: start here

Each deliverable has its own folder. Its README says what it shows, gives the headline, and names the raw
runs it was built from. Every report is generated by `evals/` from its own `report.json`, and its header names
the mode, model, prompt version, config hash, commit and date it came from. The figures these README pages
quote are checked against those report.json files by a test (`tests/test_evidence_docs.py`), so none of them
is typed by hand.

## The folders

| Folder | What it holds |
|---|---|
| [1-eval-report/](1-eval-report/README.md) | The live suite as one page (`live-11x5/`), and the offline suite (`offline-14x5/`). |
| [2-harness-ablation/](2-harness-ablation/README.md) | The live ablation as one table (`live/`), and the offline ablation (`offline/`). |
| [3-improvement-and-regression/](3-improvement-and-regression/README.md) | The live pilot before and after its fixes, the offline regression the suite catches, and the degraded prompt. |
| [4-end-to-end-workflows/](4-end-to-end-workflows/README.md) | Workflow A and B, offline and live. |
| [raw-runs/](raw-runs/README.md) | Every live invocation the pages above were built from, under its original dated name. You only need these to verify a number. |

A live invocation can stop early: on our own budget guard's cost cap, or when Google refuses calls. Its
finished runs are valid, and a combined page says which invocation each row came from, why each one
stopped, and how many of its runs the page uses. The raw reason stays in the raw run's own report.

## Making new reports

`make evals` and `make ablation` write to `raw-runs/`, and `make workflow` to `4-end-to-end-workflows/`
(`evals/layout.py`); nothing new lands at the top of this folder. A combined page is made from raw runs with
`python -m evals.report combine` or `ablation-combine`, with `--out` naming its folder.
`make check-evidence` regenerates every fixture-mode report from the code and re-derives both combined
pages from their raw runs; any difference beyond a commit and a date fails it.

## In this tree only

- `raw-runs/` also keeps the first live ablation (`2026-10-04-live-ablation-v1/` and its parts),
  superseded by the second; `make check-evidence` still re-derives its table.
- `superseded/` keeps each report as it was before a later change regenerated it, and `invalid/` keeps the
  reports of an attempt that ran on after the account's prepaid credits ran out; neither is a measurement
  in any table. Their READMEs name folders as they were when written: since this layout, a raw run is under
  `raw-runs/` by the same name, the fixture suites and the offline ablation are `1-eval-report/offline-14x5/`,
  `3-improvement-and-regression/regression-caught/` and `2-harness-ablation/offline/`, and the combined pages are
  `1-eval-report/live-11x5/` and `2-harness-ablation/live/`.
